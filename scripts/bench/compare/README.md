# Local Kosha vs OpenSearch comparison

A small harness one machine can run. It does **not** reproduce the 10M MS MARCO
numbers in [docs/benchmarks.md](../../../docs/benchmarks.md). Those need the
bench VM and the corpus snapshot. This directory answers a narrower question:
given one synthetic corpus, what do OpenSearch 2.18.0 and a published Kosha
image report for single-client BM25 latency and top-k overlap?

No result from this harness is checked in. [RESULTS.md](RESULTS.md) is a
placeholder. If you run it, commit the JSON only together with the machine,
the image digests, and the corpus seed. Do not paste a laptop run into the
README table.

Elasticsearch is not started here. `scripts/bench/run_benchmark.py` talks to
the OpenSearch bulk and `_search` APIs. Pointing that script at Elasticsearch
is untested.

## What it runs

| Piece | Pin |
| --- | --- |
| OpenSearch | `opensearchproject/opensearch:2.18.0` (the version named in `scripts/bench/render_report.py`; security plugin off) |
| Kosha | `decoverai/kosha:0.1.0` (override with `KOSHA_IMAGE`) |
| Corpus | 2,000 documents, seed 42, text aimed at 400 bytes per document, generated by `prepare_corpus.py`. `manifest.json` records the actual byte count |
| Workload | `scripts/bench/run_benchmark.py --mode lexical`, 20 repetitions per query, first request of each query is an untimed warmup inside that script |
| Auth | `KOSHA_AUTH=disabled` on the Kosha container. `run_benchmark.py` does not send a key. Do not use this compose file as a deployment. |

The publication-scale run is `scripts/bench/bm25_scale/vm/run_lucene.sh` (workflow suites `opensearch` and `elasticsearch`), against the 10M MS MARCO corpus on the bench VM. `load_corpus_opensearch.py` is the loader that script calls. It is not this 2,000-document smoke test.

## Run

Docker, Python 3, and `requests` (`pip install requests`).

```bash
scripts/bench/compare/run_local.sh
```

The script writes `scripts/bench/compare/out/`, which is gitignored:

- `corpus.jsonl`, `queries.json`, `manifest.json`
- `results.json` from `run_benchmark.py`

OpenSearch wants a high `vm.max_map_count` (the usual 262144). If the
container exits during bootstrap, that sysctl is the first thing to check.

To build Kosha from this checkout instead of pulling the published tag:

```bash
KOSHA_IMAGE=kosha:local scripts/bench/compare/run_local.sh --build-kosha
```

`--build-kosha` runs `docker build -t kosha:local` at the repo root, then
sets the image to `kosha:local` unless `KOSHA_IMAGE` is already set.

## Recording a result

Replace the placeholder sections in `RESULTS.md` with the summary block from
`out/results.json` (`modes.lexical.summary`) and this header:

- date
- `docker image inspect` digests for `decoverai/kosha:0.1.0` (or the local image id) and `opensearchproject/opensearch:2.18.0`
- CPU, RAM, and disk of the machine
- `manifest.json` from the corpus (`docs`, `seed`)
- the sentence that this is a single-client microbench, not the 8 QPS MS MARCO run
